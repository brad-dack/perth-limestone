# Local Service Lead-Gen Template

A config-driven static website template for local service lead generation
(rank-and-rent). Plain HTML/CSS/JS — no build step, no framework, no
external fonts. Designed for GitHub Pages with a custom domain.

**Swapping niche/city: edit [`config.js`](config.js), run `node bake.js`,
run `node bake.js --check`, commit the regenerated files.** `config.js` is
the only file you edit by hand — everything else is regenerated from it.
`bake.js` is a manual helper you run yourself — not a build pipeline;
nothing runs automatically and the deployed site stays plain static files.

## How it works

At load time, `js/main.js` reads `window.SITE_CONFIG` from `config.js` and
renders the page content (services, areas, FAQs, pricing, how-it-works,
forms), brand colors, and the GA4 snippet. Each service page is mapped to a
service by the `page` field on its config entry; each area page is mapped
by its `slug` (the file is `<slug>.html`).

**What's baked into static HTML (for SEO — crawlers see it before any JS
runs):** each page's `<title>`, meta description, canonical URL, Open Graph
tags, JSON-LD (LocalBusiness on every page; FAQPage where FAQs exist;
Service + BreadcrumbList on service pages; BreadcrumbList on area, FAQ,
about, and privacy pages), the H1, and the `<noscript>` name/phone
fallback.

**Everything derived is regenerated by one command:**

```
node bake.js
```

That rewrites all page HTML **plus** `CNAME`, `robots.txt`, `sitemap.xml`
(built from the actual list of pages generated, so it can never drift),
`404.html` (name/phone from config), and `favicon.svg` (brand color from
config). The only static asset it doesn't generate is `images/og-image.png`
— a neutral illustration containing no business details, so it doesn't
need changing per niche (replace it with a real photo if you have one).

**Before launch, run the preflight:**

```
node bake.js --check
```

It writes nothing and fails loudly (exit 1) listing every leftover
placeholder (domain, city, 555 numbers, tracking/form IDs), missing or
orphaned page file, sitemap/disk drift, domain mismatch, missing image or
image dimensions, and duplicate meta title/description. Warnings (non-
fatal) fire if `testimonials`/`photos` are populated — a reminder that
those must only ever contain real content.

## Swap-niche checklist

1. Edit `config.js` (all the content lives there, top to bottom — details
   below).
2. Run `node bake.js` to regenerate every derived file (pages, CNAME,
   robots.txt, sitemap.xml, 404.html, favicon.svg).
3. Run `node bake.js --check` and fix everything it flags.
4. Commit the regenerated files.

What to edit in `config.js`:

1. **business** — name, phone (both `tel:` and display format), email, city,
   state, service area, hours.
2. **domain** — used for canonical URLs, schema, OG tags, and to generate
   `CNAME`, `robots.txt`, and `sitemap.xml`. You never edit those three by
   hand.
3. **brand** — accent color, a darker hover shade, and the text color used
   on top of the accent. The favicon is generated from these. Also pick the
   visual theme here (`style` + `pattern`) — see "Making each site look
   different" below.
4. **ga4Id** — your GA4 measurement ID. **Required before launch**: while it
   contains `XXXX`, the tracking snippet is not injected, so you get no
   analytics and no `click_to_call` events — meaning no call-volume proof
   to show a future renter. (The placeholder is safe to develop with.)
5. **formspreeId** — create a free form at [formspree.io](https://formspree.io),
   copy the ID after `/f/` in the endpoint. **Required before launch: the
   site cannot capture web form leads until this is a real ID.** Until
   then, submitting the form shows a polite error with the phone number as
   fallback — phone calls work, web leads are silently lost.
6. **schema.type** — a [LocalBusiness subtype](https://schema.org/LocalBusiness)
   matching the niche (`Plumber`, `Electrician`, `RoofingContractor`, …).
7. **pages** — meta titles/descriptions and message-matched headlines. Make
   each headline mirror the exact search phrase the page targets.
8. **services** — 3 to 5 entries. Each maps to one `service-N.html` stub via
   its `page` field.
   - **Fewer than 5 services?** Remove the config entries and delete the
     unused `service-N.html` files (bake and `--check` will flag orphans);
     the sitemap updates itself on the next bake.
   - **Want keyword URLs?** Rename a stub (e.g. `service-1.html` →
     `drain-cleaning.html`) and update that service's `page` field; the
     sitemap follows automatically.
9. **areas** — 0 or more suburb/area pages targeting "service + suburb"
   searches (ships empty; nothing renders until populated). Each entry's
   `slug` becomes the page filename, so make it the keyword URL you want
   (e.g. `epoxy-flooring-joondalup`). Area pages link back to the service
   pages and homepage, and the homepage grows an "Areas We Serve" section.
   Write genuinely local content per area — near-duplicate pages with the
   suburb swapped get filtered out of search results.
10. **faqs / howItWorks / about / contact** — the site copy.
11. **images** — the homepage hero and each service have an `image` entry
    (`src`, `alt`, `width`, `height`). To swap niches: drop new files into
    `/images` and update `src` + `alt` in config — no code changes.
    - Use optimized **JPG or WebP**, roughly 1200×800, ideally under ~150KB
      (there's no build step, so optimize before committing — e.g.
      [squoosh.app](https://squoosh.app)).
    - Keep `width`/`height` accurate to prevent layout shift.
    - Write `alt` text that literally describes the image (good for
      accessibility and image SEO).
    - **Responsive variants.** An image entry may also carry
      `widths: [400, 560, 720, 960]` and a `sizes` string (use the shared
      `FIGURE_SIZES` / `INTRO_SIZES` constants at the top of config). That
      builds a `srcset`, so a phone downloads a 400px file instead of the
      full-size one — worth ~130KB per image on mobile. Each listed width
      needs a real file beside the original, named
      `images/<name>-<width>.webp`; resize them yourself (squoosh, or
      `npx sharp-cli`) and `node bake.js --check` will fail if one is
      missing. Omit `widths` and the single full-size file is used as before.
    - The shipped `.svg` files are neutral placeholder illustrations that
      work with any brand color; replace them with real photos when a
      renter supplies them. **Don't use stock photos pretending to be the
      business's own work.**
    - How-it-works step icons are inline SVGs built into `js/main.js` —
      pick per step via `icon:` from: `phone`, `chat`, `clipboard`,
      `check`, `calendar`, `wrench`, `bolt`, `home`.

## Making each site look different

Every deployment can have its own look without touching CSS. Three knobs in
`config.js` combine into the theme, and everything else (tints, glows,
shadows, the footer color, even the favicon shape) is derived automatically:

1. **`brand.color` / `colorDark` / `colorContrast`** — the palette. One
   accent color drives the whole site: pale section washes, tinted borders,
   colored button shadows, and a matching dark footer are all computed from
   it by `bake.js` (and re-derived at load time by `js/main.js`).
2. **`brand.style`** — the design personality:
   - `classic` — clean and trustworthy; soft gradient hero, rounded cards
   - `bold` — full-color gradient hero with a diagonal edge, pill buttons,
     heavy headings
   - `soft` — heavily rounded corners, pale tinted sections, blob-shaped
     imagery, rounded font (where the OS has one)
   - `sharp` — squared corners, hard borders, offset solid shadows,
     uppercase section headings
   - `elegant` — serif display headings, framed imagery, thin rules, quiet
     and premium
3. **`brand.pattern`** — a subtle background texture on the hero, page
   headers, and CTA band: `none`, `dots`, `grid`, `diagonal`, or
   `crosshatch`. Patterns are pure CSS gradients (zero requests) and adapt
   automatically to light and colored backgrounds.

The chosen style/pattern is baked onto the `<html>` tag and the derived
palette into each page's `<head>` by `node bake.js`, so the final look
renders on first paint with no flash and no JS required for styling.
`bake.js` (and `--check`) validate the values and fail loudly on typos.

None of this affects SEO: titles, meta, schema, H1s, and the noscript
fallback are baked exactly as before, there are still no external fonts or
requests, and all motion (scroll reveals, hover lifts) is CSS/JS that
respects `prefers-reduced-motion` and degrades to fully-visible static
content when JavaScript is off.

A quick way to pick a combination: temporarily change `style`/`pattern` in
`config.js` and reload your local preview — `js/main.js` applies the config
values live, so you can flip through looks before baking.

## Real-evidence placeholders (do not fake these)

`testimonials` and `photos` in `config.js` are **intentionally empty**. The
"What Customers Say" and "Recent Work" sections exist in the template but
stay hidden until these arrays contain real, verifiable content from an
actual operating business. Never populate them with invented names, star
ratings, or review counts — that's a legal/ethical liability (FTC fake
review rules) and gets renters angry when discovered.

## Deploy to GitHub Pages

1. Create a public repo and push all files to the root of the default branch.
2. Repo → Settings → Pages → Source: "Deploy from a branch" → your default
   branch, `/ (root)`.
3. Custom domain: put your bare domain in `CNAME` (GitHub fills the Pages
   setting from it), then point DNS at GitHub Pages:
   - `A` records for the apex: `185.199.108.153`, `.109.153`, `.110.153`, `.111.153`
   - `CNAME` record for `www` → `<username>.github.io`
4. Enable "Enforce HTTPS" once the certificate is issued.
5. Submit `sitemap.xml` in Google Search Console.

## Local preview

Any static file server works, e.g.:

```
npx serve .
# or
python -m http.server 8080
```

(Opening files via `file://` won't work reliably — the pages fetch nothing,
but browsers restrict some behavior on file URLs.)

## File map

| File | Purpose | Edit when swapping niche? |
|---|---|---|
| `config.js` | ALL niche content and settings | **Yes — the only one** |
| `bake.js` | Manual helper: regenerates everything below; `--check` preflight | Run after config edits |
| `index.html`, `service-*.html`, area pages, `faq.html`, `about.html`, `privacy.html` | Page shells + baked SEO head/H1/schema/noscript, baked hero, inlined CSS | Regenerated by `bake.js` |
| `CNAME`, `sitemap.xml`, `robots.txt` | Domain-bearing static files | Regenerated by `bake.js` |
| `404.html` | Not-found page (name + phone from config) | Regenerated by `bake.js` |
| `favicon.svg` | Browser tab icon (brand color from config) | Regenerated by `bake.js` |
| `images/` | Hero + service images, `og-image.png` (link previews) | Swap image files |
| `js/main.js` | Render engine (incl. `click_to_call` GA4 event on tel: links) | No |
| `css/styles.css` | Styles incl. all theme presets (colors/style/pattern come from config). Still the only file you edit, but it is now **inlined into every page** by `bake.js` rather than linked — re-run `bake.js` after changing it | No |

## Why the pages look the way they do (performance)

Three things in the generated HTML exist purely so the site loads fast on a
phone, and they're easy to undo by accident:

- **The whole stylesheet is inlined** in each page's `<head>`. A linked
  stylesheet blocks the first paint for an extra round trip. Edit
  `css/styles.css` as normal and re-run `node bake.js`.
- **The hero is baked**, not rendered by JavaScript: headline, sub-headline,
  both buttons, the value props and the hero image are all in the HTML.
  That's the visitor's first screen, and it used to wait on `config.js`
  downloading and parsing. `main.js` skips `.hero-dynamic` when it already
  has content, so **hero copy changes need `node bake.js`** to show up.
- **The hero has no entrance animation.** `main.js` adds `html.anim` after
  the page has already painted, so any fade-in on hero elements hides the
  headline and image and re-reveals them a second later — Google measures
  that later moment as Largest Contentful Paint. Below-the-fold content
  animates via `.reveal` instead, where the cost is zero.
